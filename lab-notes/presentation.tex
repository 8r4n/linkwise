\begin{frame}{Objective and guardrails}
  \begin{block}{Goal}
    Independently implement a modem in Rust that interoperates with VARA HF
    and can be installed on macOS, Windows, and Linux.
  \end{block}
  \begin{itemize}
    \item Separate a portable protocol/DSP core from OS audio and packaging.
    \item Use evidence-led compatibility tests; UI strings are leads, not specs.
    \item Keep the implementation independent of decompiled reference code.
    \item Limit dynamic radio tests to controlled, non-radiating setups.
  \end{itemize}
\end{frame}

\begin{frame}{Work completed so far}
  \begin{enumerate}
    \item Installed Ghidra 12.1.4 and the matching GhidraMCP 7.0.0 extension.
    \item Extracted the supplied VARA HF v4.9.0 installer payload.
    \item Imported the installer and actual application into Ghidra; saved
          Recon bookmarks.
    \item Installed Rust 1.99.1 and six macOS/Windows/Linux ARM64/x86\_64
          target libraries.
    \item Created a dependency-free crate with API, audio, modem, and platform
          boundaries.
    \item Organized supplied reference assets and began these lab records.
  \end{enumerate}
\end{frame}

\begin{frame}{What the reference tells us -- and does not}
  \begin{itemize}
    \item The v4.9.0 application is a 32-bit Windows PE executable; Ghidra
          reports 808 functions.
    \item UI text documents a TCP Command Port default of 8300.
    \item Ghidra string references map command/status text (CQFRAME, LISTEN,
          DRIVELEVEL, VERSION, CONNECTED/DISCONNECTED, BITRATE) to code.
    \item The binary carries VB6 Winsock/serial-control metadata.
    \item Audio UI has separate input/output device selection and signal
          diagnostics.
    \item Three mode-named data files exist: 500, 2300, and 2750.
  \end{itemize}
  \begin{alertblock}{Not yet established}
    Command framing/direction, socket roles, modem frame format, modulation,
    coding, sample rates, DSP details, and adaptive-link state machine.
  \end{alertblock}
\end{frame}
