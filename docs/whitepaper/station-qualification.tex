\section{Qualification roadmap}\label{sec:roadmap}

\paragraph{Freeze and secure the Rocky candidate.}
Record the public revision, waveform, package, and installed binary
digests. Use the production signing and repository trust configuration
for a clean installation, an upgrade from the supported starting
version, and rollback or recovery after an interrupted upgrade.
Accept only authorized signatures and demonstrate rejection of an
altered package. Verify preserved accounts, configuration and journal,
safe service defaults, SELinux enforcing, loopback bindings, and
post-recovery managed BW500 and mail TLS. Record the actual TLS module
and policy against the deployment requirements. This gate can run
while native and reference development continues.

\paragraph{Qualify the native session and radio release.}
Bind the commissioned client and device adapters to one session owner.
Carry owner and epoch through playback, acknowledgments, cancellation,
and release. Pass concurrent admission and wrong-owner trials. Account
separately for queued, acknowledged, and unresolved bytes, and demonstrate
bounded queues under backpressure, socket loss, restart, and abort.
Commission the actual radio, firmware, Hamlib backend, and audio
interface with the transmit path inhibited. Then use a controlled
conducted route and independent RF output and PTT instrumentation.
Set numerical presentation, turnaround, and release limits in the
commissioning profile before the test. Measure the worst observed
release against the approved bound during audio and host loss, stale
readback, concurrent control, process stall or crash, and power loss.
An independent watchdog and physical emergency stop must force release.
Confirm a fault latches receive-only and that key-up requires deliberate
recovery after independent release verification.
\repolink{docs/architecture/safety-security-reliability.md}{Safety and commissioning requirements}.

\paragraph{Close interoperability and planning gaps.}
Freeze the candidate, waveform hash, reference versions, and bridge
calibration. Use an unmodified stock peer and require three consecutive
passes per required bandwidth, role, payload and fault row. Count all
attempts in the record, identify missed injections and failed runs, and
retain directional payloads, audio, actual injection and retry markers,
application outcomes, and both disconnects. Close BW500 intermediate and
final ACK-loss and mixed Pat rows, including the Pat-to-Express sender
close. Repeat the wide sign-off after relevant runtime changes.
In parallel, connect authorized live RMS channel data and a pinned
VOACAP runner. Test provenance, stale or partial inputs, and fallback,
then compare ranking policies against measured outcomes on held-out
scenarios with denominators and uncertainty reported. Require a historic
ranking to replay from its recorded inputs.

\paragraph{Commission one authorized RMS/CMS exchange.}
Proceed after the signed-package, native safety, and applicable
interoperability and input gates pass. Use an approved station profile,
permitted channel, authorized account and client, and an agreed test
gateway and window. Capture the station permit, independently verified
release, and separately observed modem and client transfer, CMS
acceptance, and recipient retrieval. Include an abort or a failed
transfer with safe recovery and no unsupported delivery state. Extend
qualification to each additional hardware or operating-system profile
using the same applicable gates.

\paragraph{Qualify Windows distribution separately.}
On native x64 and ARM64 Windows hosts, verify the archive hash, import
under WSL~2, complete first-user setup, check the installed RPM, confirm
service defaults, and rerun managed BW500 after an opt-in start.
Qualify host connectivity, audio or CAT access, and FIPS if claimed
for a supported Windows and WSL kernel configuration.
\repolink{docs/install/windows-wsl.md}{Windows import and verification}.
