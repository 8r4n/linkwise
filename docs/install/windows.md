# Linkwise Modem Preview for Windows

Linkwise provides a two-way software modem, station diagnostics, and local
modem simulations. See Station Setup for audio routing and transmit settings.

Encrypted P2P transfer is available in a source build with the
`secure-transfer` feature. This installer omits the feature.

## Install or update

1. In Settings → System → About, check System type. Choose the
   `windows-arm64.exe` installer for Arm or `windows-x86_64.exe` for x64.
2. Run Setup. It installs for the machine and requires administrator rights.
   To update, run the newer installer. Restart the station after upgrading.
3. Open **Linkwise Modem PowerShell** from Start and run:

   ```powershell
   .\linkwise-modemd.exe --version
   .\linkwise-modemd.exe --simulate
   ```

The simulation runs locally without a radio. Development installers can be
unsigned. If Windows rejects the installer, ask the distributor for a signed
build.

## Set up your station

Open **Station Setup** from Start for device and configuration instructions.
Save `station.json` in your Documents folder and pass its full path to the
station commands. For example:

```powershell
$station = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'station.json'
.\linkwise-modemd.exe --check-station $station
```

If capture is denied, check Settings → Privacy & security → Microphone and
the setting that allows desktop apps to access it.

## Run the modem service

Place `station.json` under `%ProgramData%\Linkwise` using an administrator
account. Save the file and any referenced profile inside the installer-created
directory so they inherit its permissions. Administrators and SYSTEM can
write there, and Local Service has read and traverse access.
Start or stop the service from Services or elevated PowerShell:

```powershell
Start-Service LinkwiseModem
Stop-Service LinkwiseModem
```

The wizard can configure native capture and playback or a radio-free waveform
peer. For native audio, verify both devices under Local Service in Session 0.
The Application event log reports audio readiness separately from SCM state. A fresh install
uses manual startup. View lifecycle and capture diagnostics in Event Viewer
under Windows Logs → Application, source `LinkwiseModem`.

## Uninstall

Close running Linkwise commands. In Settings → Apps → Installed apps,
uninstall **Linkwise Modem Preview**. Station files saved in Documents
remain available.

## Verify receive through VB-Audio

On a test VM with VB-Audio installed, configure the station input as
`CABLE Output (VB-Audio Virtual Cable)`, channel 0. Set
`"verify_bw500_fixture": true` in the station configuration and restart
the service. From a logged-in desktop, run this command from the repository
root:

```powershell
cargo run --locked --release --manifest-path rust/Cargo.toml --features audio-device --example play_bw500_fixture -- "CABLE Input (VB-Audio Virtual Cable)"
```

Connect to the station status port and check that `exact_fixture_matches`
increases. The service increments it only for a BW500 level-2 frame with
the exact 22-byte test payload and control byte. Remove the setting after
testing and restart the service.

## Guided Winlink Express setup

Use **Configure Linkwise for Winlink** when installed with the configuration
wizard. The wizard shows the exact host and ports to enter in Express and can
open the Application event log. The [Winlink quick start](winlink-quick-start.md)
covers the radio-free BW500 P2P workflow.

## Connect Winlink Express for a radio-free BW500 P2P test

Stop the service and set `bw500_profile` to the verified measurement
profile generated by `python tools/fetch-modem-profile.py` from the
repository root. Copy the profile into the protected configuration directory
and use its filename in the configuration. Set `winlink_test_audio_port`
to 8302, leaving `command_port` and `data_port` at 8300 and 8301.
Restart the service.

Connect an isolated waveform peer to TCP 8302 before opening the Winlink
session. The existing `--virtual-audio-device` command can connect that
socket to two independent virtual audio routes. Run the bridge in a logged-in
desktop session when the audio driver requires it. See the
[modem runtime guide](../../rust/docs/modem-runtime.md#serve-a-radio-free-bw500-session)
for the wire format and bridge arguments.

In Winlink Express, open **VARA HF P2P**, use `127.0.0.1` and command port
8300, and configure the DATA port as 8301 where exposed. Use the same
station callsign in Linkwise and Express. Keep the stock VARA process
closed and disable its auto-launch if configured. Select BW500.
To switch to native audio, use the wizard or remove
`winlink_test_audio_port` and set `bandwidth` in the station configuration.
